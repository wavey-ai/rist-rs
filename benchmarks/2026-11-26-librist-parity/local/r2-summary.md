Definitions (all tables; one row of `cases.csv` per case, receivers aggregated):

- **frame latency** is measured from the frame's *scheduled* time, `due_n = t0 + n / 24 s`
  (tx `t0_ns`), to its completion at the receiver (`frames.csv` `complete_ns`), so time the
  sender spent blocked inside the transport (would-block spins, send waits) is charged to the
  transport. The CSV's `lat_p50/p99/max_ms` are tb's own figures (from the sender's handoff
  time); `lat_sched_max_ms` is the scheduled-time maximum.
- **frames lost**: frames the sender scheduled that a receiver did not complete (all parts,
  CRC-checked; `summary.json` `frames_lost`). **late-lost**: frames that completed, but later
  than the deadline `base + L + frame bytes / rate + margin` after their scheduled time, where
  L = the case's configured latency/deadline (`latency_ms`; udp gets its family's rule
  max(4·RTT, 40 ms)) and margin = 10 ms + the path's base band. SRT, librist and RaptorQ drop
  such a frame themselves; udp and a CPU-bound rist-rs receiver deliver it late. The 10 ms is
  calibrated on the deadline-enforcing transports: on nyc/syd librist and SRT complete frames
  up to about 7.5 ms beyond base + band + L + serialisation (their own release jitter on large
  frames), so a smaller slack would mark frames they delivered on their own schedule as late. *worst* = the
  receiver with most lost; *sum* over receivers. **lost %** = worst lost / frames expected.
- **carried whole** = status `ok`, 0 frames lost **and** 0 late-lost on every receiver, no
  sender-limited flag (librist `backlog_after_linger`/`unsent_at_close`/`write_failed` > 0; srt
  `units_not_sent` > 0 or a peer `stalled`/`broken`; rist-rs tx
  `errors`/`retry_send_errors`/`sessions[].pending_at_end` > 0 or rx `errors` > 0; raptorq
  `send_errors` > 0 or any receiver `errors`; udp `send_errors` > 0), and the sender's worst
  frame no later than the orchestrator's sanity threshold (500 ms; the deadline check above is
  the real lateness gate).
- **ceiling** = the largest rung carried whole with every lower rung of the same condition
  also carried whole. A `failed` case (lab broke) or a missing case is unknown, not a break.
  *highest whole* = the largest rung carried whole at all (differs when results are
  non-monotonic; one run per case, so a single frame can decide).
- **base one-way delay** (`base_ms`): udp reference cases (no loss/jitter/outage, fan-out 1,
  status ok; on real paths also udp cases with loss, since loss does not delay udp's complete
  frames, when they kept >= 10 of them) are fitted, per complete frame, as latency = base + bytes x slope, with one
  common slope per path (the median of the references' OLS slopes; *rate* = 1 / slope) and each
  reference's base = its median residual. The case's base is the **lower envelope** (minimum)
  of those bases: over every udp reference on the path for the real paths (nyc, syd), over the
  references at the same RTT on netem paths (lon, local). **band** = max - min of those bases,
  i.e. how far the path's own delay moved between cases; it is printed as ± next to added
  latency on real paths. (Raw minimum frame latencies spread wider than the band because they
  still contain each frame's serialisation.) In this data the real paths' fitted bases were nyc: 30.3-35.6 ms over 6 udp references (band 5.3 ms); syd: 125.5-125.9 ms over 6 udp references (band 0.4 ms). The sender binds an ephemeral source port, so each case's 5-tuple, and with it its route, can differ; chrony offsets stayed in the tens of µs, so this is the path, not the clocks. Without a reference: base = rtt/2 on netem paths with the
  slope of any udp case on the path (lossy ones too: only complete frames are fitted); when the
  run has no udp case on the path at all (e.g. a local run of rist cases only), the median
  slope of the same path name in the other loaded runs and the `--baseline-csv` rows
  (`base_source` says "(other run)"), so the deadline still has a serialisation term; n/a on
  real paths. The slope is fitted on TS frames; for RaptorQ it is applied to fMP4 fragment
  bytes, and RaptorQ's repair symbols also take wire time, so its serialisation term is
  approximate.
- **added latency** p50/p99 = frame latency - base - frame bytes x slope (the frame's own
  serialisation; TS bytes, fMP4 fragment for RaptorQ), over **all** frames expected on the
  receiver, a lost frame counting as +∞; the receiver with the worst p99 is reported. p99 is
  `lost` (n/a) when more than 1 % of that receiver's frames were lost, p50 when more than 50 %
  were. Negative values (a case on a faster route than the envelope) are shown as ≤0. With
  `--no-frames`: tb's summary p50/p99 minus base minus the serialisation of the median / p99
  frame. On real paths a difference smaller than the band is not significant (`n.s.`).
- **cores** = CPU seconds (user+sys, `getrusage`) per second of media (`cpu_s / duration_s`);
  sender `cpu_total` incl. linger (`tx_cores_send_phase` excludes it); receiver mean over
  receivers. **CPU/Gbit/s**: sender cores / (media Gbit/s x fan-out); receiver mean cores /
  media Gbit/s. Media rate = the rung's H.264 ES rate (`media/<rung>/media.json` `es_mbps`).
- **CPU-saturated**: a single-threaded receiver (rist-rs, raptorq, udp) at >= 0.85 cores; a
  pinned receiver core >= 95 % busy with tb at >= 0.5 cores (Linode only, not local runs:
  the shared dev box's other load shows up there; for the multi-threaded librist and libsrt
  receivers only this test applies); or the sender at >= 0.85 cores.
- **wire bytes** (`wire_tx_bytes`): bytes the sender host put on its data interface during the
  case = interface tx bytes (`iface.tx`) **plus the packets netem dropped on that egress**
  (`tc.tx.stats_after`, netem `dropped` x its mean packet size): netem drops after the
  transport sent, before the interface counter. `wire_tx_delivered_bytes` is the post-netem
  counter alone. *reverse* likewise on the receiver host; it includes SSH/chrony on nyc/syd,
  so `feedback_bytes_est` subtracts the median reverse bytes of udp cases on the same path (udp
  sends no feedback). All include IP/UDP headers. **overhead** = wire bytes / (ES bytes sent x
  fan-out) - 1.
- **repair %** = extra packets / data packets: ARQ retransmits (rist-rs `retransmits`, librist
  `retransmitted_packets`, srt `retransmits` + `fec_packets_sent`), RaptorQ (repair symbols x
  fan-out + ARQ reply datagrams) / (source symbols x fan-out).
- **recovery** (set D): the first frame scheduled after the outage end (latest restore of the
  two hosts' netem) from which three frames in a row complete within the receiver's
  pre-outage p99 + max(5 ms, 10 % of its p50) (scheduled-time latency), minus the outage end.
  ∞ if never.
- Status `failed` = the lab broke (not a result); `transport_failed` = the transport did not
  deliver (a result). Cells: ✓ = 0 frames lost and 0 late-lost, `+N late` = N frames late-lost,
  `TF` = transport_failed, `SL` = sender-limited, n/a = no data.
